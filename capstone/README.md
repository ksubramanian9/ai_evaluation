# Capstone

Build and evaluate one system end to end. Every step produces a named deliverable, has an acceptance criterion, and lists the nodes it exercises. A step's deliverable is the evidence for moving those nodes to `practiced`, and for L2 nodes it can count as the "applied once outside the exercise" part of their done bar.

- **Stage 1 (steps 1–9): RAG question-answering app** over this repo's own map.
- **Stage 2 (steps 10–12): tool-using agent** that extends stage 1.
- **Step 13** closes the loop with reporting and documentation.

## Decisions (made 2026-11-21)

| Decision | Choice | Why |
|---|---|---|
| Document set | This repo: `map/**/*.md` (nodes) and `research/*.md`. Exclude `landscape/`, which is volatile. | You know the content well enough to label answers and judge faithfulness yourself. It's small, free, and has natural structure (branches, prerequisites) for slicing results. |
| Model and provider | Claude for both roles: generator `claude-sonnet-5-5`, judge `claude-opus-5-5`. | The judge comes from a different model than the generator, following [llm-as-judge](../map/03-measurement-methods/llm-as-judge.md). One provider keeps setup simple. Record exact model IDs in every result file, because model choice is volatile. |
| Hosting | Python on your machine. CI eval gate in GitHub Actions. Traces to local JSONL files, or a self-hosted Langfuse if you want a UI. | Cheapest option, and it exercises [ci-eval-gates](../map/05-testing-in-engineering/ci-eval-gates.md) for real. Production-branch steps use simulated traffic (see step 9). |

Code lives in `capstone/` (for example `capstone/app/`, `capstone/evals/`, `capstone/data/`), and results go to `capstone/results/<date>-<step>.md`.

**Acceptance thresholds** below are proposed starting points, not sourced standards. Where a step says "baseline", set the number from your own first measurement and its variance, then fix it before iterating ([baselines-and-thresholds](../map/02-eval-design/baselines-and-thresholds.md)).

## Stage 1: RAG over the map

| # | Step | Deliverable | Acceptance criterion | Nodes exercised |
|---|---|---|---|---|
| 1 | **Define the task and success criteria.** Who asks what (a learner asking about eval concepts), what a good answer is, what must never happen (an uncited claim, an answer from outside the map presented as the map's view). | `capstone/results/…-task.md`: task statement, 3–5 quality dimensions, a pass/fail definition per dimension, out-of-scope questions. | Every dimension has a written pass/fail rule that two people could apply the same way. | [task-definition-and-success-criteria](../map/02-eval-design/task-definition-and-success-criteria.md), [quality-dimensions-taxonomy](../map/02-eval-design/quality-dimensions-taxonomy.md), [evaluation-mindset](../map/01-foundations/evaluation-mindset.md) |
| 2 | **Build the golden dataset.** About 100 questions with reference answers and the node IDs that support them. Write about 60 by hand; generate about 40 synthetically and review them. Include unanswerable questions. Slice by branch, by question type (definition, comparison, how-to) and by answerability. | `capstone/data/golden-v1.jsonl` plus a datasheet: sources, slices, how the synthetic items were filtered, a version tag. | Every slice has at least 10 items. A 20% holdout is split off and never looked at during iteration. Synthetic items are labelled as such. | [golden-datasets](../map/02-eval-design/golden-datasets.md), [synthetic-data-generation](../map/02-eval-design/synthetic-data-generation.md), [coverage-and-slicing](../map/02-eval-design/coverage-and-slicing.md), [data-splits-and-leakage](../map/01-foundations/data-splits-and-leakage.md), [contamination-and-leakage](../map/02-eval-design/contamination-and-leakage.md), [eval-dataset-versioning](../map/02-eval-design/eval-dataset-versioning.md) |
| 3 | **Build the baseline app and harness.** A simple chunker, one retriever and one generator prompt. The harness records dataset version, model IDs, prompt hash and per-item outputs. | `capstone/app/`, `capstone/evals/run.py`, and the first results file. | One command reruns the whole eval, and two runs on the same config produce comparable result files. | [eval-harness-design](../map/03-measurement-methods/eval-harness-design.md), [llm-basics-for-evaluators](../map/01-foundations/llm-basics-for-evaluators.md), [prompt-versioning-and-change-management](../map/05-testing-in-engineering/prompt-versioning-and-change-management.md) |
| 4 | **Run retrieval evals.** Recall@k, MRR and nDCG@k against the supporting node IDs. Compare BM25 with one embedding retriever. | Results file with a metric table per slice and a bootstrap CI on the difference. | You can say which retriever is better, with a CI, and on which slices. | [rag-retrieval-evals](../map/04-system-specific-evals/rag-retrieval-evals.md), [ml-metrics](../map/01-foundations/ml-metrics.md), [confidence-intervals-for-evals](../map/03-measurement-methods/confidence-intervals-for-evals.md) |
| 5 | **Run generation evals with a validated judge.** Label about 50 answers yourself for faithfulness and correctness. Write a judge rubric and validate the judge against your labels before trusting it. Run a position-swap and a verbosity probe. | Judge prompt and rubric (versioned), an agreement table (kappa or alpha) with a confusion matrix, a bias probe write-up, then full-set generation scores. | Judge agreement with your labels is at least as high as your agreement with yourself on a re-label of 20 items a week later, and kappa ≥ 0.6 as a working floor (a common convention, not a sourced standard). Bias probes are reported even if they pass. | [rag-generation-evals](../map/04-system-specific-evals/rag-generation-evals.md), [rubric-design](../map/02-eval-design/rubric-design.md), [llm-as-judge](../map/03-measurement-methods/llm-as-judge.md), [judge-bias-and-calibration](../map/03-measurement-methods/judge-bias-and-calibration.md), [inter-rater-agreement](../map/03-measurement-methods/inter-rater-agreement.md), [annotation-guidelines](../map/02-eval-design/annotation-guidelines.md) |
| 6 | **Do error analysis and one iteration.** Read failing traces, build a failure taxonomy, fix the top category and re-measure. Check variance by running each config 3 times. | Failure taxonomy with counts, before/after results with a paired CI, a variance note. | The claimed improvement holds on the holdout and exceeds run-to-run variance. | [error-analysis](../map/01-foundations/error-analysis.md), [nondeterminism-and-variance](../map/01-foundations/nondeterminism-and-variance.md), [statistical-inference](../map/01-foundations/statistical-inference.md), [eval-driven-development](../map/02-eval-design/eval-driven-development.md), [rag-end-to-end-evals](../map/04-system-specific-evals/rag-end-to-end-evals.md) |
| 7 | **Add a regression suite and CI gate.** Fast deterministic unit checks (citations present, valid node IDs, refusal on unanswerable questions) on every PR. A cached judge-scored subset runs on PRs that touch prompts; the full suite runs nightly. | `.github/workflows/capstone-evals.yml`, unit tests, a gate threshold derived from step 6 variance. | A deliberately seeded regression (for example, a prompt edit that drops citations) fails the gate, and an unchanged rerun passes it. | [regression-testing](../map/05-testing-in-engineering/regression-testing.md), [ci-eval-gates](../map/05-testing-in-engineering/ci-eval-gates.md), [llm-unit-tests](../map/05-testing-in-engineering/llm-unit-tests.md), [programmatic-checks](../map/03-measurement-methods/programmatic-checks.md), [determinism-control-and-mocking](../map/05-testing-in-engineering/determinism-control-and-mocking.md), [flaky-test-management](../map/05-testing-in-engineering/flaky-test-management.md) |
| 8 | **Red team and test robustness.** Paraphrase and typo perturbations with metamorphic relations (same question, same supporting nodes). Prompt-injection probes planted in a test copy of a node file. Off-topic and harmful requests. | Robustness table, an injection test set, and a findings log with each finding turned into a regression case. | Every finding is either fixed or recorded as accepted risk, and each has a regression test. | [robustness-testing](../map/05-testing-in-engineering/robustness-testing.md), [metamorphic-and-property-testing](../map/05-testing-in-engineering/metamorphic-and-property-testing.md), [red-teaming](../map/05-testing-in-engineering/red-teaming.md), [prompt-injection-security-testing](../map/05-testing-in-engineering/prompt-injection-security-testing.md), [safety-and-harm-evals](../map/05-testing-in-engineering/safety-and-harm-evals.md) |
| 9 | **Add tracing and simulated production.** Trace every call (retrieval, prompt, output, cost, latency). Replay a simulated traffic stream (golden questions plus new phrasings from an LLM user simulator validated against your own questions); redact anything personal before traces reach the judge, sample 10% for judge scoring, and feed failures back into the dataset as `golden-v2`. Then change the model or prompt as a canary and check for drift. | Trace files, a sampled-judge dashboard or notebook, a cost and latency summary, and `golden-v2` with a changelog. | You can trace any bad answer back to its retrieval and prompt version, and the canary comparison reports a difference with a CI. | [observability-and-tracing](../map/06-production/observability-and-tracing.md), [traffic-sampling-and-logging](../map/06-production/traffic-sampling-and-logging.md), [production-evals-with-judges](../map/06-production/production-evals-with-judges.md), [feedback-loop-to-datasets](../map/06-production/feedback-loop-to-datasets.md), [drift-detection](../map/06-production/drift-detection.md), [shadow-and-canary-releases](../map/06-production/shadow-and-canary-releases.md), [model-upgrade-and-migration](../map/06-production/model-upgrade-and-migration.md), [performance-latency-cost-testing](../map/05-testing-in-engineering/performance-latency-cost-testing.md), [privacy-and-pii-in-eval-data](../map/06-production/privacy-and-pii-in-eval-data.md), [user-simulation-evals](../map/04-system-specific-evals/user-simulation-evals.md) |

## Stage 2: tool-using agent

The agent answers study questions by calling tools over the same corpus: `search_map(query)`, `read_node(id)`, `prerequisites(id)` and `study_path(goal)`. Tools return structured results. For safety, `read_node` refuses paths outside `map/`.

| # | Step | Deliverable | Acceptance criterion | Nodes exercised |
|---|---|---|---|---|
| 10 | **Run task-success evals.** About 30 multi-step tasks (for example, "what should I study before judge-bias-and-calibration, and why?") with programmatic end-state checks. Run each task k times. | Task set, pass@k and pass^k per task, a cost per completed task. | Both pass@k and pass^k are reported with k stated, and the gap between them is explained. | [agent-task-success-evals](../map/04-system-specific-evals/agent-task-success-evals.md), [nondeterminism-and-variance](../map/01-foundations/nondeterminism-and-variance.md), [eval-cost-management](../map/07-operating-practice/eval-cost-management.md) |
| 11 | **Run trajectory and tool-use evals.** Check tool choice and argument validity, and look for redundant calls. Grade end states rather than exact paths. | Tool-call accuracy table, a trajectory rubric, a judge validated as in step 5. | Every trajectory metric has a stated reason for why it predicts task success or cost. | [agent-trajectory-evals](../map/04-system-specific-evals/agent-trajectory-evals.md), [tool-use-evals](../map/04-system-specific-evals/tool-use-evals.md) |
| 12 | **Run agent security tests.** Plant injection instructions in a node file the agent reads, try path traversal through `read_node`, and run the agent in a sandbox with no network. | Injection and abuse test set with results; sandbox configuration. | No test causes an action outside the tools' stated contract. Any failures are fixed and added to the regression suite. | [prompt-injection-security-testing](../map/05-testing-in-engineering/prompt-injection-security-testing.md), [sandboxing-untrusted-code](../map/03-measurement-methods/sandboxing-untrusted-code.md) |
